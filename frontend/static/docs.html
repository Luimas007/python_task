API Reference

Every endpoint is served by the FastAPI application on http://127.0.0.1:8000. All responses are JSON. The interactive OpenAPI explorer is at /docs.

The database is the only knowledge source. No endpoint reaches the public internet at query time. The single exception is POST /api/knowledge/refresh, which is the build step that fills the database in the first place — and even that falls back to the locally saved pages the moment GSMArena denies access.

Authentication

None. The service binds to 127.0.0.1 and is intended for local use, so there are no API keys, tokens or session cookies. Every request below works as-is. If you expose it beyond localhost, put a reverse proxy with authentication in front of it — nothing in this codebase does that for you.

The only header you ever need is Content-Type: application/json, and only on POST requests.

How a request flows

POST /api/ask
   │
   ▼
NEXUS (orchestrator)  ── plans the run
   │
   ├─► ATLAS      reads the question, resolves phone names   ── SELECT phones
   │
   ├─► SPECTRA    fetches the specifications                 ── SELECT phone_attributes
   │              ORACLE  semantic search                    ── cosine_similarity()
   │              RANKER  league tables                       ── ORDER BY … LIMIT
   │
   ├─► VERSUS / CRITIC / NEXUS   write the answer            ── Ollama (localhost)
   │
   └─► SENTINEL   checks every figure against the evidence
   │
   ▼
JSON response  { answer, intent, agents_used, grounding, trace }

Endpoints

POST /api/ask

Ask a question. This is the endpoint the chat interface uses. It runs the whole multi-agent pipeline and returns the answer plus the full trace.

Request body

FieldTypeRequiredDescription
questionstringyes 2–2000 characters.
session_keystringno Groups turns into one stored conversation. Defaults to anonymous.

Example request

curl -X POST http://127.0.0.1:8000/api/ask \
  -H "Content-Type: application/json" \
  -d '{
        "question": "Which Samsung phone has the best battery life?",
        "session_key": "demo"
      }'

Example response (trimmed)

{
  "run_id": "a1b2c3d4e5f6",
  "question": "Which Samsung phone has …",
  "answer": "The Samsung Galaxy S26 Ultra has the
             best battery life, at 16.4 hours.",
  "intent": "ranking",
  "agents_used": ["NEXUS","ATLAS","RANKER","SENTINEL"],
  "pipeline":    ["ATLAS","RANKER","NEXUS","SENTINEL"],
  "devices": [],
  "unresolved": [],
  "grounding": {
    "verdict": "grounded",
    "numeric_claims": 1,
    "supported": 1,
    "unsupported": [],
    "support_ratio": 1.0
  },
  "latency_ms": 977.6,
  "trace": [ … ]
}

Response fields

FieldMeaning
intentOne of spec_lookup, compare, ranking, review, general — decided by ATLAS.
agents_usedWhich agents actually ran.
devicesPhones resolved against the phones table.
unresolvedModel names mentioned but not in the database. The answer says so rather than inventing them.
groundingSENTINEL's audit: how many numeric claims in the answer were traced back to retrieved rows.
extrasIntent-specific payload — the ranking table, comparison deltas, or review standings.
traceEvery agent message and database round-trip for this run.

What the knowledge base currently holds, and whether a refresh is running.

  "phones": [ { "phone_id": 1, "model_name": "Samsung Galaxy S26 Ultra",
                "series": "Galaxy S", "rank": 2 } ],
  "default_limit": 10
}
POST /api/knowledge/refresh

Scrape the most popular Samsung phones and rebuild the knowledge base. Returns immediately; progress streams over /ws/trace as kb.* events. Only one refresh may run at a time.

FieldTypeDefaultDescription
limitint 1–10010 How many phones to load.
replacebooltrue Replace the knowledge base rather than adding to it.
offlineboolfalse Skip the network and rebuild from data/pages/.
curl -X POST http://127.0.0.1:8000/api/knowledge/refresh \
  -H "Content-Type: application/json" \
  -d '{"limit": 10}'

{ "started": true, "limit": 10, "stream": "/ws/trace" }
If GSMArena denies access (HTTP 429/403), the pipeline stops requesting immediately and finishes from the locally saved pages. The same parser runs either way, so the stored data is identical. Poll GET /api/knowledge/refresh/status if you cannot hold a WebSocket open.
GET /api/phones

Every phone in the knowledge base with its headline attributes.

curl http://127.0.0.1:8000/api/phones
GET /api/phones/{phone_id}

The full specification sheet for one device: typed attributes plus every verbatim spec row, grouped by category. Fields the source never published come back as null.

curl http://127.0.0.1:8000/api/phones/1
{
  "phone": { "model_name": "Samsung Galaxy S26 Ultra",
             "battery_capacity_mah": 5400,
             "display_protection": null },
  "specs_by_category": {
    "Display": [ { "key": "Size",  "value": "6.9 inches, …" },
                 { "key": "Protection", "value": null } ]
  }
}

404 if no phone has that id.

GET /api/rankings

League table over one whitelisted numeric attribute. Phones whose value is NULL are excluded and counted, never guessed at.

Query paramTypeDefaultDescription
metricstringbattery_endurance_hours Must be one of /api/rankable. Anything else returns 400.
limitint 1–3010Rows returned.
curl "http://127.0.0.1:8000/api/rankings?metric=battery_capacity_mah&limit=5"
{
  "column": "battery_capacity_mah",
  "label": "battery capacity",
  "unit": "mAh",
  "direction": "DESC",
  "rows": [ { "model_name": "Samsung Galaxy S26 Ultra", "metric_value": 5400 } ],
  "excluded_null_count": 0
}
GET /api/agents

The agent roster: name, role, capabilities, which protocols each speaks, and whether it touches the database or the language model.

curl http://127.0.0.1:8000/api/agents
GET /api/protocols

The five transports the system labels in its trace: PG-WIRE/3.0, VEC-SQL/1.0, ACP/1.0, OLLAMA-HTTP/1.1, WS-TRACE/1.0.

GET /api/health

Database, LLM, embedding model and corpus status. Use this first when something is not working.

curl http://127.0.0.1:8000/api/health
{
  "status": "ok",
  "database": { "ok": true, "endpoint": "localhost:5432/samsung_kb",
                "protocol": "PG-WIRE/3.0" },
  "llm":      { "ok": true, "model": "llama3.2:3b" },
  "embedding":{ "model": "…/all-MiniLM-L6-v2", "dim": 384, "device": "cpu" },
  "corpus":   { "phones": 10, "chunks": 237 }
}

status is degraded when the LLM is unreachable — the API still answers, returning database rows instead of prose.

GET /api/history

Stored conversation for a session. Params: session_key (default anonymous), limit (default 40).

curl "http://127.0.0.1:8000/api/history?session_key=demo"
GET /api/query-log

The audit trail: every SQL statement the agents ran, with the agent that issued it, row count and duration. Proof that answers came from the database.

curl "http://127.0.0.1:8000/api/query-log?limit=20"
WS /ws/trace

Live event stream. Two families:

EventWhen
agent.start / agent.end An agent begins or finishes. Carries an activity string — the sentence the chat shows.
acp.messageOne agent hands off to another.
db.queryA SQL round-trip, with the statement and timing.
kb.*Knowledge-base refresh progress.
// browser console on http://127.0.0.1:8000
const ws = new WebSocket("ws://127.0.0.1:8000/ws/trace");
ws.onmessage = e => console.log(JSON.parse(e.data));

Using Postman

Eight steps to run any endpoint above. The example uses POST /api/ask, the one worth demonstrating.

1
Open Postman Launch the desktop app (or web.postman.co). You can skip signing in — click Skip and go to the app. Make sure the assistant is running: python app.py.
2
Create a request Click New → HTTP, or press the + above the tab bar. An untitled request opens with a method dropdown and a URL field.
3
Select the HTTP method Open the dropdown on the left of the URL bar (it says GET) and choose POST. Use GET for every read endpoint above — those need no body at all.
4
Enter the URL 
http://127.0.0.1:8000/api/ask
Use 127.0.0.1 rather than localhost; on some Windows setups localhost resolves to IPv6 first and the connection is refused.
5
Add the header Open the Headers tab and add:
KeyValue
Content-Typeapplication/json
Postman usually adds this for you when you pick a JSON body in the next step — check it is there. No authentication header is needed.
6
Add the request body Open the Body tab, choose raw, and set the format dropdown on the right to JSON. Paste: 
{
  "question": "How does the Galaxy S25 Ultra compare to the S24 Ultra?",
  "session_key": "postman-demo"
}
7
Send Click Send. The first question after startup takes a few seconds while the language model loads; later ones return in about one second for lookups and rankings, and five to ten for comparisons and reviews.
8
Read the response The bottom pane shows the JSON, the status code and the elapsed time. What to look at:
FieldWhat it tells you
answerThe prose reply.
agents_usedWhich agents ran — the multi-agent flow, in order.
grounding.verdictgrounded means every number in the answer was matched to a database row.
traceExpand it to show the actual SQL each agent issued. This is the proof the answer came from PostgreSQL.

Error responses

StatusMeaningBody
400A parameter was valid JSON but not an allowed value — e.g. a metric outside the whitelist. {"detail": "metric must be one of: …"}
404No phone with that id. {"detail": "no phone with id 999"}
409A knowledge-base refresh is already running. {"detail": "a knowledge base refresh is already running"}
422The body failed validation — missing question, or it was empty. {"detail": [ { "loc": ["body","question"], … } ]}

There is no 401 or 403: the API is unauthenticated by design.
